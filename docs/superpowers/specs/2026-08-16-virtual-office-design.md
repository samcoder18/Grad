# Виртуальный «Офис компании» — дизайн раздела

Дата: 2026-08-16
Проект: `sladkiy-grad-redesign` (Vite + React 19, Tailwind 4, GSAP/motion, без роутера и бэкенда)

## Контекст и цель

На лендинге «Сладкий град» появляется раздел «Офис компании» — **витрина-концепт** виртуального офиса. Это не рабочий продукт: бэкенда нет, данные моковые, цель — наглядно и полно показать цифровую инфраструктуру компании для B2B-аудитории (партнёры, оптовики, заказчики).

Важна **полнота покрытия модулей** (по ТЗ): структура компании, ассистент холодных переговоров, сделки, ЭЦП, партнёрская сеть, удалённое взаимодействие с клиентами.

## Ключевые решения (согласованы при брейншторме)

- **Формат**: отдельный полноэкранный вью внутри SPA, переключение из Nav, без роутера — на состоянии React (view-switch).
- **Раскладка**: дашборд с сайдбаром.
- **Группировка сайдбара**: три группы — «Компания», «Сделки», «Развитие».
- **Интерактивность**: сценарные мини-демо на мок-данных (не статика, не полная имитация с глобальным состоянием).
- **Стиль**: гибрид — тёмный сайдбар (ink `#17191c`) + светлая контентная область (paper `#f7f8f6`, белые карточки, малиновый акцент `#d91e36`). Наследует токены из `src/index.css`.
- **Интеграция**: подход 1 — view-switch без hash-роутинга и MPA.

## Архитектура

- `src/App.jsx` — состояние `view: 'landing' | 'office'`. Переключение через `AnimatePresence` (fade+slide). Лендинг размонтируется; кнопка «← На сайт» в офисе возвращает лендинг.
- `src/components/Nav.jsx` — новый пункт «Офис» (десктоп + мобильное меню), вызывает `onEnterOffice`.
- Офис подключается через `React.lazy` + `Suspense` (скелетон на время подгрузки) — код офиса не попадает в начальный бандл лендинга.

### Структура файлов

```
src/components/office/
  OfficeShell.jsx        # каркас: сайдбар + топбар + контентная область
  modules.js             # реестр модулей: { id, title, icon, group, component }
  Leadership.jsx         # руководство
  Department.jsx         # один параметризованный компонент для 3 отделов
  Deals.jsx              # переговоры по сделкам
  Contracts.jsx          # договоры по ЭЦП
  ColdCallAssistant.jsx  # ассистент холодных переговоров
  PartnerNetwork.jsx     # партнёрская сеть
  Clients.jsx            # удалённое взаимодействие с клиентами
src/data/office.js       # все мок-данные
```

Сайдбар и контент строятся из реестра `modules.js` — добавление модуля = одна запись. Три отдела — это три записи реестра на один компонент `Department` с разными `props.departmentId`. Активный модуль — `useState` в `OfficeShell`.

### Адаптив

На мобильных (< 768px) сайдбар превращается в нижнюю панель навигации с иконками модулей; контент — в одну колонку.

## Модули и сценарии мини-демо

### Группа «Компания»

- **Руководство** (`Leadership`) — карточки топ-менеджеров: CSS-аватар с инициалами, должность, зона ответственности, кнопка «Написать» → мок-чат с автоответом. Сверху орг-сводка: 4 подразделения, N сотрудников.
- **Отдел** (`Department`, три экземпляра: Продажи, Финансовый, Финансово-административный) — шапка с описанием и KPI-плашками; список сотрудников; вкладка «Задачи недели» (мок-борд). Характерный виджет на отдел: продажи — воронка по стадиям; финансовый — график оплат; фин.-административный — реестр документов. Один компонент + разные данные и один виджет.

### Группа «Сделки»

- **Сделки** (`Deals`) — слева список сделок с партнёрами/заказчиками (стадия, сумма), справа мок-чат выбранной сделки: история + кнопки предложенных ответов; по клику сообщение добавляется, «собеседник» отвечает с задержкой ~1 с. Сверху таймлайн стадий сделки.
- **Договоры по ЭЦП** (`Contracts`) — список договоров со статусами (черновик / на подписании / подписан). Просмотр договора (PDF-заглушка) → пошаговый флоу: «Проверка сертификата → Подписание → Отправка контрагенту» с анимацией, финальный штамп «Подписан» + мок-хэш подписи.

### Группа «Развитие»

- **Ассистент холодных переговоров** (`ColdCallAssistant`) — сценарный тренажёр звонка: «клиент» произносит реплику, менеджер выбирает один из 3 вариантов ответа; ассистент подсвечивает лучший и объясняет почему (скрипт, работа с возражениями). Финал — сводка: шаги, ошибки, совет.
- **Партнёрская сеть** (`PartnerNetwork`) — список партнёров по регионам, карточка партнёра (объём закупок, статус), блок «Стать партнёром» с мок-формой заявки → экран «Заявка принята».
- **Клиенты** (`Clients`) — лента обращений из каналов (мессенджер / почта / звонок), мок-чат поддержки с автоответами, виджет «Видеовстреча» (заглушка-превью комнаты).

Состояние каждого сценария живёт только внутри открытого модуля; при переключении модуля сбрасывается — для витрины это осознанное и предсказуемое поведение.

## Данные

`src/data/office.js` — единственный источник мок-данных:

- `leadership` — руководители (имя, должность, зона ответственности, реплики автоответа);
- `departments` — три отдела (название, описание, KPI, сотрудники, задачи, данные виджета);
- `deals` — сделки (контрагент, тип partner/customer, сумма, стадии, история чата, варианты ответов);
- `contracts` — договоры (номер, контрагент, статус, шаги флоу подписания);
- `coldCallScript` — дерево сценария тренажёра (реплики клиента, варианты ответов, оценка, объяснения);
- `partners` — партнёры (регион, объём, статус);
- `tickets` — обращения клиентов (канал, тема, история, автоответы).

Поток односторонний: `office.js` → компоненты. Глобального стора нет.

## Стиль и UX

- Токены из `src/index.css`: paper `#f7f8f6`, ink `#17191c`, line `#e3e6e2`, brand `#d91e36`, radius `28px`, шрифты Unbounded (заголовки) / Onest (текст).
- Сайдбар тёмный (ink), контент — paper с белыми карточками и малиновым акцентом.
- Анимации — `motion` (уже в зависимостях): переход вью, появление сообщений в чатах, шаги флоу ЭЦП. Уважение `prefers-reduced-motion`.
- Доступность: навигация сайдбара с клавиатуры, видимые focus-состояния, `aria-label` на интерактивных мок-элементах.

## Ошибки и краевые случаи

Сети нет, поэтому обработка ограничена:

- пустые состояния списков (нет сделок / обращений / документов);
- отключённые кнопки вне активного шага сценария;
- скелетон `Suspense` при первой подгрузке офиса;
- новые графические ассеты не нужны (CSS-аватары, иконки Phosphor).

## Проверка и приёмка

Тестового раннера и линтера в проекте нет — не добавляем ради витрины. Приёмка:

1. `npm run build` — без ошибок.
2. Smoke-прогон через dev-сервер: переход лендинг ↔ офис, все 7 модулей открываются, интерактив каждого мини-демо работает (ответы в чатах, шаги ЭЦП, тренажёр, форма заявки).
3. Мобильная раскладка (< 768px): нижняя навигация, одна колонка.

## Не входит (YAGNI)

- Бэкенд, аутентификация, реальная ЭЦП и криптография.
- Роутер и deep links (URL-адресация модулей).
- Сохранение состояния между переключениями модулей и перезагрузкой.
- Реальные видеозвонки, файлы, PDF-рендер.
